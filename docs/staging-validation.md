## Compatibility review

Apply migration **001 before 002**. Both use transactions and end with `COMMIT`; neither deletes movies or seeds accounts/films. Empty movies are supported: no migration depends on existing rows. An existing published-only permissive SELECT policy can remain: CineWave adds restrictive guards and its own permissive policies. An existing restrictive policy can additionally block administrator access and must be reviewed, not silently removed.

001 requires `genre_names text[]`, an automatically generated `id` that is the sole primary key, the original movie columns used by the UI/trigger (including `title_en`, `release_date`, `watch_url`, `is_published`, `created_at`, `updated_at`), Supabase `auth.users`/`auth.uid()`, `anon`/`authenticated` roles, and RLS-enabled `storage.buckets`/`storage.objects`. It adds rights/rendition columns, a private allowlist, RPC, trigger, grants and policies. It creates or reconfigures the reserved public image bucket `cinewave-assets` (8 MiB, JPEG/PNG/WebP); an existing compatible bucket still has its limits overwritten. Stop for any bucket collision requiring review. Public images are intentionally public; do not upload private material.

002 requires the 001 RPC/private schema and an `integer` or `bigint` movie ID. UUID movie IDs are incompatible. It adds `media_type text NOT NULL DEFAULT 'movie'` with a movie/tv check, private `profiles` and `user_watchlist` tables, grants, restrictive owner policies and a timestamp trigger. It does not grant admin rights. Watchlist foreign keys cascade if an operator later deletes a movie/user; do not exercise deletion in this validation.

`IF NOT EXISTS` is not schema reconciliation: existing same-named tables, functions, triggers, policies, constraints and columns need comparison before execution. In particular 002 does not fully validate an unrelated existing profiles/watchlist table or the definition of a same-named media-type constraint. Stop rather than assuming compatibility. Neither SQL file is a complete audit of unrelated security-definer RPCs or pre-existing Storage policies. Supabase-managed Storage ownership/DDL privileges must be tested with the approved owner connection.
